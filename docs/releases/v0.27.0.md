# Vittics Builder 0.27.0 — projects that stop say why, and use fewer tokens

Two pilots of tiny tools showed where Vittics Builder wastes time and tokens. A personal one-page checklist used
12.7M input tokens, 86% of them on legal, support and documentation tickets. It then sat idle for two hours after
reaching a limit, with nothing on the Decisions page to say so.

## What changed

- **A project that stops tells you why.** On reaching its repair or agent-run allowance, or stopping for any other
  reason (nobody can take a ticket, a reviewer gave no verdict), the CTO gets a decision with the reason and the open
  tickets: **Allow more and continue**, **Try again** or **Pause project**. Raising a limit applies to that project
  only, with no `org.yaml` edit and no restart. Nothing is retried or logged again while a decision waits, and tickets
  that failed without reaching the CTO are now escalated.
- **Saner default allowances:** 6 repairs and 150 agent runs for a Standard project, 2 and 60 for Small
  (`pipeline.max_project_repairs` and `max_project_runs` still override them; `null` turns a limit off).
- **Ghost runs are cleared** at start-up: runs left "running" by a closed or crashed app no longer count toward
  limits or look busy.
- **Fewer tokens.** Reviewers get the ticket's diff and the check results in their prompt and a budget of about a
  dozen tool calls. Builders read only what their ticket needs. Every agent follows a document rule (create a new
  document only when asked, keep it short, link instead of restating) and must quote numbers only from real output.
  An internal tool is no longer given legal, support or documentation tickets unless the assessment found a need.
- **Size: Auto** is the new default for new projects: Small for a simple local tool (single page, personal,
  localStorage, calculator) that asks for nothing heavy, otherwise Standard. The choice and its reason are logged;
  you can still pick Small or Standard yourself.
- **Costs shows cached versus fresh input**, and each project's calls and tokens.
- **An expired login pauses work** with the exact sign-in command (`claude auth login`, `codex login`) instead of
  failing tickets. New hires on a subscription no longer log an "ANTHROPIC_API_KEY is not set" warning.
- **Remove project** (project page, CEO only; `vittics-builder delete-project ID`) permanently removes a project and
  everything it made, in one all-or-nothing step, after you type its name.
- **The sidebar shows which build this is**, for example `0.27.0+abc1234`.

This release also includes the changes merged since 0.26.0 (verification holds for human evidence, remote MCP
connections, department editing, approval switches, adaptive review by default for new companies, stage timings and
more); see CHANGELOG.md.

## Install

- **macOS (Apple Silicon):** Quit Vittics Builder, open the DMG, and drag the app into Applications. Choose Replace
  if prompted. If macOS cannot verify it, use System Settings → Privacy & Security → Open Anyway.
- **Windows (x64):** Quit Vittics Builder and run the setup installer.

Existing company data is kept; new columns are added automatically. Existing projects keep their size.

## Limits

The token savings are estimates from two pilots, not a measurement: rebuild a small project on this version and
compare. Agents still start from scratch on every run (no session resume yet) and there are no per-run turn caps.
Desktop installers are unsigned; macOS bundle integrity and bundled-backend startup are checked in CI.
