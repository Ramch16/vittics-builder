# Vittics Builder 0.27.1 — accept what only a person can check

The first pilot rebuilt on 0.27.0 showed a trap: release QA kept stopping for checks only a person can do, and each
retry spent another round of tokens (17.4M input in all).

## What changed

- **Accept without human checks** on the "Human verification required" decision (CTO). It needs a reason, which is
  kept on the release record. QA is not repeated for that exact version, and the acceptance lapses if the product
  changes. Failed checks cannot be accepted.
- **Retry verification** on an unchanged product now explains that nothing changed instead of repeating QA.
- **Small projects** skip the market and legal opinions; feasibility remains.
- **Turn caps** for Claude Code: 80 turns for builders, 30 for reviewers, QA and auditors (`llm.cli_max_turns`,
  `llm.cli_review_turns`).
- The release summary notes when documents far outweigh the code.
- **Costs** shows each project's input tokens by kind of work.

## Install

- **macOS (Apple Silicon):** Quit Vittics Builder, open the DMG, and drag the app into Applications. Choose Replace if
  prompted. If macOS cannot verify it, use System Settings → Privacy & Security → Open Anyway.
- **Windows (x64):** Quit Vittics Builder and run the setup installer.

Existing company data is kept; a new column is added automatically.

## Limits

Agents still start from scratch on every run (no session resume). The token saving of 0.27.0 is still not measured on
a clean run. Desktop installers are unsigned.
