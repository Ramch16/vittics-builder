Vittics Builder

An open-source software company staffed by AI agents, run by two people, with a benchmark that asks whether its review-heavy workflow beats a single agent.

Status: benchmark built and tested offline. No real comparison has been run yet.

The question

Given the same frozen requirements, starter code, public tests, model and resource caps, how does the Vittics multi-role workflow (builder, independent code review, QA, rework) compare with one persistent builder on independent hidden-test acceptance, false releases, rework and resource use?

What exists

PartState
Eight synthetic tasks with hidden testsBuilt; every starter fails and every reference passes 81 checks
Independent oracleRuns the frozen public and hidden tests on a fresh copy of the final tree

Both conditions and run recordsBuilt; records validated against a JSON schema
Hard per-run token, cost and time capsBuilt and tested
Security controlsReview minimums, secrets sandbox (Linux, macOS), Docker limits, sign-in rate limit

What does not exist yet

Results. The only runs so far used scripted offline agents to test the pipeline; they say nothing about either condition. A real pilot needs an approved model, caps and budget, and the team's reviews of the tasks, isolation and baseline.

Reproduce it

From a clone of the repository: sh scripts/reproduce.sh. This installs the hashed lock, runs the tests, validates the tasks, regenerates the schedule, runs mock slots and freezes the output.
